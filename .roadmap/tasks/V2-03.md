# V2-03: Hexagonal & Weighted Terrain Mode in Maze Navigator

## Overview
Extend `solvers/maze_navigator.py` with **Hexagonal Grid (6-way axial/offset coordinates)** and **Weighted Terrain** support, paired with a dedicated hex-capable custom renderer `web/renderers/custom/hex_maze.js` (or conditional hex mode inside `maze_navigator`), enabling interactive editing and A*/Dijkstra/BFS visualization on pointy-top hex boards.

## Architecture & Scope
* **Solver:** `solvers/maze_navigator.py` already supports weighted terrain (`4` = `2×`, `5` = `4×`), `A*`, `Dijkstra`, and `BFS` on square grids (`4-Way`, `8-Way`, `Quarter-Arc`). This task adds `"topology": "Hexagonal (6-Way)"` (or `grid_type` param/preset field) using odd-r / even-r offset coordinates mapped to cube coordinates `(q, r, s)` for exact hex distance heuristics.
* **Frontend renderer:** Square grids continue using `web/renderers/grid.js` (`"renderer": "grid"`), or `maze_navigator` switches to `"renderer": "custom"` with `custom_view: "/renderers/custom/hex_maze.js"` that delegates to standard grid rendering when `maze_type != "Hexagonal"` and renders SVG/Canvas pointy-top hexagons when in Hex mode.

## Implementation Plan

### 1. Hexagonal Graph & Heuristic (`solvers/maze_navigator.py`)
* **Coordinate mapping:** Represent board as standard 2D `rows × cols` matrix using **odd-r offset coordinates** (odd rows shifted right by `0.5` tile width).
* **6-way neighbors:** Precompute odd-row vs. even-row neighbor offsets `[(dr, dc), ...]`.
* **Admissible A\* heuristic:** Convert `(row, col)` to cube coordinates `(q, r, s)` where `q = col - (row - (row & 1)) // 2`, `r = row`, `s = -q - r`, and use exact hex distance:
  `h = max(abs(dq), abs(dr), abs(ds))` (scaled by minimum step cost `1`).
* **Weighted terrain integration:** Reuse existing tile weights (`0` = cost `1`, `1` = wall, `2` = Start, `3` = Goal, `4` = `2×`, `5` = `4×`) uniformly across Square and Hex topologies.
* **Params & Presets:**
  * Add `"geometry"` (or `"topology"`) param: `["Square Grid", "Hexagonal (6-Way)"]` (default `"Square Grid"` so existing square presets remain unchanged).
  * Add solvable presets: `"Hex Maze 7x7"` and `"Hex Weighted Terrain 7x7"`.

### 2. Interactive Hex Renderer (`web/renderers/custom/hex_maze.js`)
* Implement `render(stage, state, highlights, onEdit, meta)` following the custom renderer contract (like `liquid_tubes.js` and `loop_board.js`).
* **Dual-mode delegation:** When `state.geometry !== "Hexagonal (6-Way)"` (and param is Square), delegate cleanly to the standard `grid.js` renderer so existing Square, Edge-Wall, and Quarter-Arc modes behave identically.
* **Hex SVG rendering:**
  * Render pointy-top hexagons with odd-row horizontal offset, themed via CSS variables (`--bg-panel`, `--accent-primary`, `--accent-secondary`, `--accent-hot`) for Chalkboard, Midnight Plum, and all built-in themes.
  * Display terrain badges (`S`, `G`, `2×`, `4×`, walls), explored frontier highlights, and smooth polyline path overlay through hex centers.
  * Click-to-cycle cell state in `EDIT` mode (`0 -> 1 -> 2 -> 3 -> 4 -> 5 -> 0`), calling `onEdit(nextState)`.

### 3. Tests (`tests/test_solvers.py`)
* Verify all new Hex presets solve cleanly in `test_solver_all_presets_solve`.
* Add unit tests comparing `A*` vs `Dijkstra` vs `BFS` on a weighted hex board (confirming `A*`/`Dijkstra` take the lower-cost path around `4×` terrain while `BFS` takes fewest hops).
* Verify unreachable hex goal returns `"failed"` with `"No path"` diagnostic.
